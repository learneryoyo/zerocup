## 一、先看这三件事

**1. 不要动别人的文件。**
每个人负责自己的 `.html` + 自己的 `.css`，文件名写着自己的名字。看到别人的文件有 bug，
在群里说，不要直接改。这样四个人永远不会撞车。

**2. 不要自己配色、自己定字体。**
颜色和字体全在 `site/css/base.css` 里，用变量取：
`color: var(--ink);` 不要写 `#43372A`。

**3. 改完就提交。**
不要攒一堆再提交。改完一个东西就提交一次，写清楚改了什么。
攒着提交，一旦出问题，没人知道是哪一步坏的。

## 三、怎么在本地看

最简单：双击 `site/index.html`。

但更推荐起一个本地服务器（因为有些功能在 `file://` 下会失效，比如读取本地文件）：

```bash
cd site
python -m http.server 8000
```

然后浏览器打开 <http://localhost:8000>

## 五、Git 三步（详细版看 `git-manual.md`）

```bash
git pull          # 1. 动手前先拉，把别人的改动拿下来
#   ...改文件...
git add .
git commit -m "首页：加了时辰轴"    # 2. 提交，写清楚改了什么
git push          # 3. 推上去
```

**记住顺序：先 pull，再改，最后 push。**
顺序反了会冲突，冲突了不要慌，看手册最后一节。

## 六、几条技术底线

这几条是踩过坑总结的，不是讲究：

- **动效只动 `transform` 和 `opacity`**。动 `width`/`height`/`margin` 会掉帧。
- **界面动效控制在 300ms 以内**。超过 300ms 会显得卡。
- **进入用 `ease-out`，不要用 `ease-in`**。`ease-in` 起步慢，慢在用户最盯着看的那一下。
- **永远不要 `transition: all`**，写明具体属性。
- **`prefers-reduced-motion` 要写**。晕动症用户会感谢你。
- **特效可以失败，内容不能消失**。用 JS 控制显示时，先给 `<html>` 加 `js` 类再让 CSS 依赖它
  （`main.js` 第一行已经做了）。
