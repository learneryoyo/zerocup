## 三、设计理念

### 3.1 立意：为什么做这个

大多数非遗网站是一块「图文展板」——看完记住的是照片，不是技艺，更不是它今天的处境。
我们想回答的问题不是「它有多美」，而是**「它还在不在」**：还有多少人在做，还有没有人在用，
如果断了，断在哪一环。

所以全站只做三件事：**看见它（辑录）→ 用上它（古艺新生）→ 掂量它还剩多少（存续有数）**。
首页那三拍，就是这三件事的顺序。

### 3.2 三个关键设计决策

**决策一：首页不做轮播，做三拍纵向叙事**

- 放弃了什么：轮播能在一屏塞进更多项目，视觉更「满」，也是同类站点的标准做法。
- 为什么：非遗当代性的问题不是「知道得不够多」，而是「用得不够多」。轮播是并列关系，
  看完只记得「有很多」；纵向三拍是递进关系，看完会记得「先是看见，然后是使用，最后是存续」。
- 代价与处理：首屏信息密度下降。用首屏底部的三枚条目（壹 百工有章 / 贰 古艺入常 / 叁 遗脉寻踪）
  把结构直接摊在读者眼前，不用滚动也知道这一页有几段。

**决策二：分类页做「选样」，不做「全录」**

- 放弃了什么：每类只收 4—5 项（四页共 17 项），页面偏短，容易被看成「内容不足」。
- 为什么：深度与广度不能兼得。十七项按「来处—工序—人—存续」四层写透，一项占一屏多；
  若为了凑数把每类补到二十项，每一项都只能剩一段简介，等于把深度换成宽度。
  宽度交给另一页：存续有数收了 114 项，按濒危程度排成一条可拖动的光谱。
- 代价与处理：两页的关系必须说清楚，否则读者会以为站点只有十七项。
  所以每个分类页开头都写明「本页是选样，不是全录」，并给出光谱页入口。

**决策三：字体自己切子集，不用系统字体，也不整包下发**

- 放弃了什么：直接调用系统宋体最省事，但全站会失去刻本的字形气质；
  直接下发整包字库（867 KB）在「网速过慢」的测试环境下等于让首屏多等十几秒。
- 为什么：这套宋刻本字形是整站气质的来源——标题、图注、名录编号都靠它统一。
  但它真正用到的字只有两千出头，一页用到的又只有几百个。
- 代价与处理：为每一页单独切一份 woff2，只含这一页会出现的字（含 CSS `content` 里生成的伪元素文字）。
  代价是**改任何文案都要重跑一次切字脚本**，否则新字会静默回落成系统宋体。这条写进了协作约定。

### 3.3 视觉与交互方案

- **配色**：纸白 `#f6efe4`、墨 `#10100f`、朱 `#a03a25`。朱色只用在「脉」——那根从首屏牵到页尾的细线、
  页脚顶边的短横、光谱上的断代标记。四类辑录各有一个传统色（青黛 / 石榴红 / 艾草青 / 桂花金），
  只在各自的页面里出现，不互相串。
- **字体**：标题与正文用宋刻本 DingLie SongKe（自建子集），页脚题记与个别标题用行书 HongLei XingShu，
  两者都按页切分，单页字体总量 19—313 KB；关于页题记与匠人日记金句另用一套 196 字的手写体（见 §6.2）。
- **版式**：单栏为主，最大阅读宽度 64em；全站间距以 `clamp()` 随视口缩放，不用固定断点硬跳。
- **动效**：滚动进入用 IntersectionObserver 触发，时长 300—700 ms；手绘长卷做景深视差；
  光谱用拖拽筛选；展柜要连叩三次才碎开。所有动效在 `prefers-reduced-motion: reduce` 下关闭，
  悬停效果包在 `@media (hover: hover)` 里，触屏设备不会出现「点一下卡住」的状态。

### 3.4 与同类作品的差异

同类非遗站点通常做成「名录 + 高清图 + 一段介绍」的百科式结构，评价标准是收录了多少项。
本站把「存续状况」做成了可操作的主线：每一项有濒危指数、有编辑判断的依据、有「想学怎么找」的渠道，
并把三十件当代文创和十七项传统技艺并置——**传统与今天不是两个板块，是同一条线的两端。**

## 五、技术方案

**整体架构**：纯静态多页站点，十七个 HTML 页面共享一套手写 CSS 与原生 JS。
内容全部硬编码在 HTML 与少量 JS 数据文件里（三十件新作、一百一十四项光谱、十七位匠人各自一个数据文件），
没有构建步骤，没有 `package.json`，没有 `node_modules`。

**自己实现的关键功能**：

1. **字体按页切子集**。用 fontTools 把 2125 字的宋刻本与 247 字的行书，按「这一页实际会出现的字」
   切成单页 woff2，并用 `<style>` 覆盖 `@font-face` 的族名，让原有规则直接命中。
   切字时会把 CSS `content:"…"` 生成的伪元素文字一并算进去——漏了它，浏览器会为几个字回落整包字体。
   单页字体从母本 912 KB 降到 19—313 KB；首页在慢网（400 kbps / 400 ms RTT）下 21 个请求 / 1131 KB，
   `load` 从 26.5 s 降到 14.7 s。
2. **长卷热区用 SVG 路径命中**。矩形热区会盖住画面大片空白，点空白也跳转。
   改为 `<path>` 描出人物与飘带轮廓，`pointer-events` 只落在路径上。
3. **滚动与视差全部自己写**。IntersectionObserver 做进入动画与章节高亮；
   `requestAnimationFrame` 做时间轴轨道的横向位移与手绘长卷的景深，未使用任何滚动库。
4. **光谱的拖拽筛选**。一百一十四项按指数排在一行，用双端滑块划定区间，实时过滤并重排；
   每项的「想学怎么找」只列官方机构与公开渠道，不含任何个人信息。
5. **展柜的叩击状态机**。六座展柜各需连叩三次，逐次累积裂纹，第三次碎开并展开明信片式详情。

**性能处理**：图片全部按显示尺寸压缩并写明 `width` / `height`（避免布局抖动）；
非首屏图片 `loading="lazy"`，首屏主图 `fetchpriority="high"`；字体 `preload` + `font-display: block`；
长卷大图在 `window.load` 之后再拉，失败时退回线条版。

**适配方案**：以 1440 为基准，`clamp()` 做连续缩放，另在 1000 / 900 / 760 / 720 / 700 px 设断点处理版式切换；
390 移动端实测无横向溢出，导航折叠为按钮。三套媒体查询分别处理「减少动效」「有悬停能力」「精细指针」。

## 九、本地预览与打包

双击 `site/index.html` 即可浏览。更推荐起本地服务器（图片较多时加载更稳）：

```bash
cd site
python -m http.server 8000
```

然后浏览器打开 <http://localhost:8000>

打包：

```bash
python package.py --team 海底小纵队 --captain 队长姓名 --names 姓名1,姓名2,姓名3,姓名4
```

产出在 `dist/`（已被 `.gitignore` 排除）：

```
dist/零杯零组-队伍名-队长姓名.zip
├── 2026-零杯零组-队伍名-队长姓名-完整版本.zip
└── 2026-零杯零组-队伍名-队长姓名-匿名版本.zip
```

脚本自动排除 `.git`、模板页、`prototypes/`、下划线开头的本地脚本与参考图，剥掉图片 EXIF，
匿名版删去成员表整段，并在包内回扫姓名、邮箱、手机号，命中即中止。

## 十一、协作约定（对内）

- 一个人只碰自己那一页，别人的文件不要动；动手前先 `git pull`。
- **改了任何文案，必须重跑 `python _font_page.py --all`**，否则新出现的字会静默回落成系统宋体。
  该脚本与切字产物在仓库根与 `site/assets/fonts/`，以 `_` 开头的临时脚本不进 git。
- 文件名一律用英文，中文写在内容里。
- 导航与页脚全站保持一致，改一处就要改所有页面。
