## 一、项目方向

### 主题

非物质文化遗产。按我们自己的分法，收五个大类：

| 大类 | 代表动作（图标就画这个） |
|---|---|
| 传统手工艺 | 拉坯 —— 俯身、耸肩、双手捧住泥坯 |
| 饮食制作技艺 | 拉面 —— 弓步后仰，双臂展开到极限 |
| 戏曲音乐曲艺 | 水袖亮相 —— 一臂高扬，袖子甩出去还在回卷 |
| 民俗节庆 | 舞龙 —— 两人踮脚后仰，龙身拱过头顶 |
| 舞蹈武术游艺 | 马步推掌 —— 低重心，整个人是个三角形 |

### 地域锚点：湖北

专题内容落在湖北。理由很实在：**团队在湖北，将来有机会实地核验和采访。**
写「我们这儿的」比写「全国各地的」更站得住，也更容易做出别人没有的细节。

### 核心手法

**用动作说话，不用道具堆砌。**

五个图标共用一套视觉：粗线墨色勾线、豆形身体、没有五官、米黄平涂。
鼠标移上去，线条会先瞬间清空，再一笔一笔重新画出来。

这个交互本身就是"手艺"的隐喻——**手艺是一笔一笔做出来的**。

## 四、怎么在本地看

最简单：双击 `site/index.html`。

更推荐起本地服务器（有些功能在 `file://` 下会失效）：

```bash
cd site
python -m http.server 8000
```

然后浏览器打开 <http://localhost:8000>

## 六、Git 三步

```bash
git pull          # 1. 动手前先拉
#   ...改文件...
git add .
```

## 七、内容规矩（最重要的一节）

非遗内容**写错就是硬伤**。评委会看出来，而且这比技术 bug 更伤。

### 1. 不许编

- 不确定的，不写
- 拿不准是不是这个地方的，写「据 XX 记载」
- **不要把某地特有的习俗写成"全国各地都有"**
- 不要为凑字数加形容词。「历史悠久、博大精深」这种话零信息量，删掉

### 2. 每条都要有出处

`docs/sources.md` 里逐条记录：项目名、来源机构、链接、核验日期。
页面上至少标一个来源，评委会点进去看。

### 3. 图片和图标

- 用自己画的（我们那套简笔画）
- 或者用明确可商用、标明出处的
- **不要随手百度一张图就放上去**——这是最常见的扣分点

### 4. 不要承诺做不到的事

- 不写「在线预约」「一键报名」，除非真的做了
- 外部链接要写清楚是「跳转到某某官网」

## 八、技术底线

这几条是踩过坑总结的，不是讲究：

- **动效只动 `transform` 和 `opacity`**。动 `width`/`height`/`margin` 会掉帧。
- **界面动效控制在 300ms 以内**。
- **进入用 `ease-out`，不要用 `ease-in`**。`ease-in` 起步慢，慢在用户最盯着看的那一下。
- **永远不要 `transition: all`**，写明具体属性。
- **`prefers-reduced-motion` 要写**。
- **特效可以失败，内容不能消失**。`main.js` 第一行给 `<html>` 加了 `js` 类，
  CSS 依赖它控制动画，JS 挂了内容还在。
- **文件名一律用英文**。中文文件名在不同系统之间会乱码，某些工具也读不了。
